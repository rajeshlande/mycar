# myCar PWA workflow

## Cache boundary

The service worker may cache only public app shell/assets: HTML, built JS/CSS/fonts, manifest, icons, and the illustrative image. It must never cache Supabase Auth/REST responses, tokens, private records, or non-GET requests.

## Before editing

1. Read `AGENTS.md`, `public/sw.js`, `public/manifest.webmanifest`, `vite.config.js`, `src/main.jsx`, and `src/lib/pwa.jsx`.
2. Identify whether the change affects installability, offline navigation, cache lifetime, or deployment path.
3. Keep sample mode separate from offline account access. Offline shell availability is not an authentication bypass.

## Rules

- Keep manifest `start_url`, `scope`, icons, and worker registration relative so `/` and `/myCar/` both work.
- Preserve build-specific cache names and cleanup limited to the current app path prefix.
- Preserve GET-only, same-origin, static-asset/public-file guards.
- Keep `precache.json` generated by the build and aligned with copied public assets.
- Account for CORS-mode asset requests when matching precached files; do not remove the static-only `ignoreVary` handling without testing offline module loading.
- Registration is production-only and must fail gracefully in embedded previews.
- Do not claim push notifications or offline financial writes exist.

## Verify

```sh
npm run build
npm run test:browser
npm run preview -- --base=/myCar/ --port 4175
```

Use a managed process for the preview. Check root and nested paths, service-worker scope, offline reload, manifest/icon resolution, and that cache entries contain no `/auth/v1/` or `/rest/v1/` URLs. Test real-device installation separately before claiming mobile install acceptance.
